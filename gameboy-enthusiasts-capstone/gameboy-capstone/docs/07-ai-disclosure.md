# 7. AI Disclosure

## Meaningful AI Use

AI assistance was used to:

- Help organize the accessibility audit structure and remediation log.
- Suggest accessible markup patterns (skip link, named `nav`, `aria-current`, form `aria-describedby` / `aria-required` / autocomplete).
- Draft or refine About page content after the original page was identified as a duplicate.
- Assist with the structure of this final evidence package (planning, architecture, release, and defense documents).

## What Was Accepted

- Skip-link and landmark patterns.
- Form accessibility attribute recommendations.
- Heading-level correction on Home.
- Overall organization of the accessibility report and evidence docs.
- Game Boy–themed token naming and system-font performance rationale already present in the stylesheet.

## What Was Rejected or Heavily Edited

- Any suggestion that core navigation or layout should depend on JavaScript (rejected to meet course constraints).
- Generic or marketing-heavy copy (kept community-focused and precise).
- Unverified claims of specific automated tool scores; only structural / manual findings are asserted.
- Any change that would remove existing strong features (`prefers-reduced-motion`, focus rings, system fonts, `@layer` architecture).

## Verification Performed

- All four HTML pages and the shared CSS were reviewed against the acceptance criteria and WCAG-oriented checks.
- Remediation items were confirmed present in source (skip links, `aria-current`, form attributes, correct About page, sequential headings).
- Internal links, image `alt` text, and asset provenance comments were checked.
- Documentation claims match the delivered files.

AI accelerated audit organization and documentation scaffolding. Final code, content accuracy, accessibility assertions, and release claims were verified by the human author.
